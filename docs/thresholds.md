# 照合の既定値と根拠

企画書 §13「閾値や探索半径の既定値は試験データで調整し、根拠を文書に残す」に対応する。値は `osm_diff_reviewer/core/profile.py` の `DEFAULT_THRESHOLDS` と `Profile` にあり、プロファイル JSON で上書きできる。

現時点(M1)の根拠は自作の試験データ(`osm_diff_reviewer/tests/data/m1/`)と一般的な位置精度の想定だけ。実データで検証したら、この表を更新する。

| 項目 | 既定値 | 根拠 |
|---|---|---|
| ポイントの探索半径 `point.search_radius_m` | 50 m | 自治体の施設一覧は住所ジオコーディング由来が多く、数十 m ずれることがある。これより遠い候補は同一施設と見なさない |
| ポイントの形状許容 `point.max_distance_m` | 15 m | 建物の入口と中心の差程度。試験データでは 5 m を一致、30 m を形状差とした |
| ポリゴンの探索半径 `polygon.search_radius_m` | 30 m | ポリゴン同士は境界間の距離で探す。重なっていれば 0 m |
| ポリゴンの重なり率 `polygon.min_iou` | 0.6 | 1 m のずれ(IoU 約 0.9)は一致、半分だけ重なる(IoU 0.5)は形状差とした |
| 最低スコア `min_match_score` | 0.4 | 総合スコアがこれ未満の候補は対応と見なさない。名称が全く違っても距離がごく近ければ「属性差」として拾える(試験データの R4:形状 0.94、名称 0.18、総合 0.56) |
| 曖昧の幅 `ambiguity_margin` | 0.05 | 1位と2位の差がこれ未満なら「曖昧」。誤って「一致」に入れないことを優先する(企画書 §12 リスク) |
| 名称の類似度閾値(属性対応表の `threshold`) | 0.8 | 「テスト商店」と「テスト商会」(0.8)は同じとみなす水準 |

## スコアの定義

- 形状スコア:ポリゴン同士は IoU。それ以外は `1 − 距離 / 探索半径`(ポイントがポリゴンの内側なら距離 0)。
- 属性スコア:属性対応表の各項目のスコアの平均。両側とも空の項目は数えない。対応表がなければ属性スコアは無し。
- 総合スコア:形状と属性の平均。属性スコアが無いときは形状スコアのみ。

## 対応付けの規則

1. 探索半径内で総合スコアが最低スコア以上のものを候補とする。
2. 参照地物ごとに1位と2位の差が曖昧の幅未満なら「曖昧」。
3. 曖昧になった参照地物の上位候補(1位との差が曖昧の幅未満)の OSM 地物は、その参照地物のために確保する。
4. 残りをスコア順に貪欲に一対一で割り当てる。同じ OSM 地物を取り合い、差が曖昧の幅未満なら双方「曖昧」。
5. 候補はあったがすべて他の参照地物に取られた参照地物は「未登録」ではなく「曖昧」にする。
6. ライン(M5 で対応)は照合対象外とし、件数を警告で示す。OSM 側のラインも候補にしない。

## 距離を測る座標系

プロジェクト CRS が投影系でメートル単位、かつメルカトル系でなければそれを使う。それ以外(地理座標系、Web メルカトル EPSG:3857、フィート単位など)は参照データ中心の UTM 帯を使う。Web メルカトルは緯度が上がるほど距離が伸び(東京で約 1.23 倍)、閾値が実質的に変わってしまうため除外している。

## レビューの引き継ぎ(M2)

- 判定は「参照データ名 + 参照キー + OSM 種別・ID」に結び付けて保存する。未登録の候補は OSM 側が空、OSM のみの候補は参照キーが空になる。
- 判定時の参照ハッシュ(形状と、空でない属性値から計算)と OSM の version を記録し、再実行時にどちらかが変わっていれば「要再確認」にする。OSM の version が取れないデータでは OSM 側の変化は検出できない。
- 「曖昧」の候補は1位の OSM 地物に結び付けて保存する。編集で1位と2位が入れ替わると別の組とみなされ、判定は引き継がれない(要再確認にもならない)。曖昧の候補は判定を保留にしておく運用を勧める。
- 参照 ID フィールドを指定しない再実行では、前回記録したフィールドを使う。別のフィールドを指定すると警告を出す(判定は引き継がれない)。
- ライセンス記録は参照データ名に結び付く。データの取得元(レイヤのソース)か ID フィールドが変わると、確認状況は「未確認」に戻る。
