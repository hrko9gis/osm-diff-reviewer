# OSM Diff Reviewer 利用手順

参照データ(自治体のオープンデータなど)と OpenStreetMap を QGIS 上で照合し、差分を更新候補として確認するための手順です。プラグインは OSM を編集しません。編集は JOSM(個人作業)か MapRoulette(共同作業)で行います。

## 1. 準備

### 必要なもの

- QGIS 3.40 LTR 以降(QGIS 4 系にも対応)。QGIS の表示言語が日本語なら画面も日本語になります。
- 参照データのレイヤ。地物ごとに変わらない ID フィールドがあることが望ましい(なければ形状と属性から作るハッシュで代用しますが、参照地物が少しでも変わると別の地物扱いになり、判定が引き継がれません)。
- OSM データのレイヤ。OSM の種別・ID・version を属性に持つもの(既定のフィールド名は `osm_type`、`osm_id`、`osm_version`)。
  - Overpass API から取得したデータ、JOSM で保存した `.osm`、`.osm.pbf` などが使えます。QGIS で `.osm` / `.osm.pbf` を開くと GDAL の OSM ドライバが使われ、種別は自動で判定されます。
  - version がないと、判定後に OSM 側が編集されたことを検出できません(照合時に警告が出ます)。GDAL の OSM ドライバは既定で version を読み込まない(`osmconf.ini` の `osm_version=no`)ため、version を使うには `osm_version=yes` にした `osmconf.ini` を用意する(環境変数 `OSM_CONFIG_FILE` で指定)か、version を属性に書き出せるツール(QuickOSM など)でデータを取得してください。
- JOSM を使う場合:JOSM の 設定 > リモート制御 で「リモート制御を有効にする」をオン。
- MapRoulette を使う場合:MapRoulette のユーザー設定で発行した API キー。

### 作業用 GeoPackage

照合結果とレビューの判定は、プロジェクトごとに1つの GeoPackage(作業ファイル)に保存します。レビューパネル上部のファイル欄で選ぶか、新しいファイル名を入れると作られます。選んだ作業ファイルは QGIS プロジェクトに記録され、プロジェクトを開き直すと自動で読み込まれます。

## 2. 照合する

1. メニュー「プラグイン > OSM Diff Reviewer > レビューパネル」でパネルを開き、作業ファイルを選びます。
2. 「照合を実行…」を押すと、プロセッシングの「参照データと OSM を照合」が開きます。
   - 参照レイヤ、参照 ID フィールド、OSM レイヤを選びます。
   - プロファイル(JSON)で閾値と属性対応表を指定できます(5 章)。省略時は既定値で、属性は比較しません。
   - 参照データ名は省略するとレイヤ名になります。判定の引き継ぎとライセンス記録はこの名前ごとに行われます。
3. 実行すると、パネルに最新の結果が表示されます。プロセッシングツールボックスから直接実行した場合は「再読み込み」を押します。

### 分類

| 分類 | 意味 |
|---|---|
| 一致 | 対応する OSM 地物があり、形状・属性とも閾値内 |
| 未登録 | 探索半径内に対応する OSM 地物がない |
| 形状差 | 対応はあるが、位置・形の差が閾値を超える |
| 属性差 | 対応はあるが、属性対応表の項目が食い違う |
| 曖昧 | 候補が複数あり一意に決まらない(道路の区切り方の違いなども含む) |
| OSM のみ | 参照側に対応がない OSM 地物(参照データが網羅的と指定した場合だけ) |

座標系:距離はプロジェクトの座標系がメートル単位の投影座標系(平面直角座標系など)ならその座標系で、そうでなければ参照データのある UTM 帯で測ります。Web メルカトル(EPSG:3857)は距離が伸びるため使いません。

## 3. レビューする

- 一覧の行を選ぶと地図がその場所へ移動し、参照側をオレンジ、OSM 側を青で強調します。下の表に属性を左右に並べ、食い違う項目には色が付きます。
- 状態(未確認 / 要編集 / 反映済み / 対応不要(参照側の誤り) / 対応不要(OSM が正しい) / 保留)とメモを選んで「保存」します。「次の候補」で次の行へ進みます。
- 既定では「一致」と「対応不要」は一覧に出ません。上部のチェックボックスや分類・状態の絞り込みで切り替えられます。列の見出しで並べ替えられます。

### 再実行と引き継ぎ

参照データや OSM データを更新して照合をやり直すと、前回の判定がそのまま引き継がれます。判定のあとに参照側の属性・形状、または OSM 側の version が変わった組には「要再確認」が付き、「対応不要」でも一覧に再表示されます。「要再確認のみ」で絞り込めます。

## 4. 編集ツールへ引き渡す

### JOSM

- 「JOSM で開く」:JOSM が候補の周辺(余白約 50 m)を読み込み、該当する OSM 地物を選択した状態で開きます。曖昧な候補では候補の地物をすべて選択します。
- 「次を開く」:次の候補へ移って JOSM で開きます。続けて作業するときに使います。
- 「参照地物を JOSM の別レイヤとして送る」:未登録の候補で、参照地物を提案タグ(属性対応表から作るタグ)付きの別レイヤとして JOSM に送ります。このレイヤはロックされ、アップロードできません。必要な情報を通常のデータレイヤに写して編集してください。ライセンスが確認済みの場合だけ送られます。
- JOSM での作業が終わったら、パネルで状態を「反映済み」などに更新します。「OSM で反映確認」を押すと、Overpass で OSM 地物の version を読み直して変化があったかを表示します(Overpass への反映には数分かかることがあります)。
- JOSM が起動していない、またはリモート制御が無効のときは、その旨が表示されます。

### MapRoulette

パネルの「MapRoulette…」で、一覧に表示中の候補を対象にした画面が開きます。絞り込みで対象を選んでから開いてください。

1. **GeoJSON に書き出す**:1候補を1タスクとし、分類、参照側の属性(`ref:フィールド名`)、OSM 地物の ID(`@id`)を含めます。タスクの説明文はテンプレートで作れます(`{ref_key}`、`{@id}`、`{ref:名称}` などがタスクのプロパティに置き換わります)。MapRoulette の Web 画面からこのファイルでチャレンジを作れます。
2. **チャレンジを作成**:API キーを QGIS の認証設定(「API Header」でヘッダ名 `apiKey`、または「Basic」のパスワード欄)に保存して選びます。キーは設定ファイルやプロジェクトには書かれません。「管理中のプロジェクトを読み込む」でプロジェクトを選び、名称と手順を入れて作成します。チャレンジは既定で非公開です。地域コミュニティに相談してから MapRoulette 上で公開してください。
3. **タスクの状態を同期**:MapRoulette 上のタスクの状態を判定に反映します(修正済み・既に修正済み → 反映済み、問題なし → 対応不要、スキップ・難しい → 保留)。前回の同期から MapRoulette 側の状態が変わったタスクだけを反映するので、QGIS で付け直した判定は上書きされません。

## 5. プロファイル(閾値と属性対応表)

JSON ファイルで保存し、照合のたびに指定します。例と各項目の意味は README の「Profile」と [thresholds.md](thresholds.md) を参照してください。

- `attribute_mappings`:参照フィールドと OSM タグの対応と比較方法(`exact` 完全一致、`normalized` 正規化後一致、`similarity` 類似度)。名称の比較では全角・半角、空白、「株式会社」などの法人格表記の違いを無視します。
- `thresholds`:地物の種類(point / polygon / line)ごとの探索半径などの閾値。
- `reference_is_exhaustive`:参照データがその種類の地物を網羅している場合だけ true にします。true のとき「OSM のみ」が出ます。

## 6. 参照データの版間差分

参照データの新しい版が公開されたときに、変わったところだけを OSM と照らし合わせます。プロセッシングツールボックスの「OSM Diff Reviewer > 参照データの版間差分を OSM と照合」を使います。

- 旧版・新版のレイヤと、両方にある ID フィールドを指定します(必須)。
- 結果:
  - 追加 → OSM に既にある / OSM にない
  - 削除 → OSM にまだある / OSM から消えている
  - 変更 → OSM は旧状態のまま / OSM は更新済み / 判定不能
  - 候補が絞れない場合は「曖昧」
- 作業ファイルを指定すると、結果はレビューパネルに通常の候補と同じように表示され、JOSM・MapRoulette への引き渡しも使えます(「版間の変化」列に結果が出ます)。

## 7. ライセンスの記録

参照データごとに、ライセンス名、出典表記、OSM での利用可否(未確認 / 確認済み / 不可)、根拠 URL を「ライセンス…」で記録します。

- 「確認済み」でないと、参照データを外部に出す操作(JOSM への参照レイヤ送信、GeoJSON 書き出し、MapRoulette へのチャレンジ作成)は止まります。照合とレビューはいつでもできます。
- 現在のファイルについて確認済みで出典表記があると、JOSM の変更セットの `source` に出典が入ります。
- 確認は「どのファイルについて確認したか」と一緒に記録されます。参照データの新しい版(別のファイル)で照合すると、確認済みのまま「以前のファイルについて確認済み」の状態になります。
  - この状態で書き出し・MapRoulette 送信・参照レイヤの送信をしようとすると、「このファイルにも同じライセンス条件が当てはまりますか?」と確認が出ます。「はい」を選ぶと現在のファイルについて確認したことが記録され、そのまま処理が続きます。「いいえ」なら送りません(JOSM では周辺だけ開き、参照レイヤは送りません)。
  - 利用条件が版の途中で変わることもあるので、新しい版の公開ページで条件を確かめてから答えてください。
  - 確認画面を表示している間に別のファイルで照合が実行された場合は、表示していたファイルについてだけ確認するため、記録されずにエラーになります。開き直してください。
- ID フィールドを変えて「未確認」に戻ったことも、履歴に「リセット」として残ります。
- ID フィールドを変えた場合は、別の形で整理されたデータとみなし、確認状況は「未確認」に戻ります。
- 「ライセンス…」の画面の下に、これまでの確認の履歴(日時、操作、OSM での利用可否、ファイル、ライセンス名)が表示されます。

外部データを OSM に取り込む作業は、[インポートガイドライン](https://wiki.openstreetmap.org/wiki/Import/Guidelines)の対象になることがあります。参照データのライセンスが ODbL と両立するかを確かめ、大きな作業の前には地域コミュニティに相談してください。

## 8. 設定

パネルの「設定…」で次を変更できます。

- JOSM リモート制御のアドレス(既定 `http://127.0.0.1:8111`。このコンピュータ上のアドレスだけ指定できます。プロキシは通しません)
- Overpass API の URL(既定 `https://overpass-api.de/api/interpreter`。QGIS のプロキシ設定に従います)

MapRoulette の API の URL と認証設定は「MapRoulette…」の画面で指定します。

## 9. 困ったとき

| 症状 | 対処 |
|---|---|
| 「… の JOSM に接続できません」と出る | JOSM を起動し、リモート制御を有効にする。設定のアドレスとポートを確認する |
| 参照レイヤが送られない | ライセンスを「確認済み」にする。未登録の候補でのみ送られる |
| 判定が引き継がれない | 参照 ID フィールドが前回と同じか確認する(違うと警告が出る)。ID なしで照合した場合、参照地物が変わると別扱いになる |
| 「要再確認」が大量に出た | 参照データの更新や OSM データの取り直しで、判定時から内容が変わった組が再表示されている |
| 「MapRoulette がエラーを返しました(401)」と出る | 認証設定の API キーを確認する |
| 書き出しのボタンが押せない | ライセンスが「確認済み」になっていない |
